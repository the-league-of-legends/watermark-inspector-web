# 边缘定位与非阻塞失败处理

- 自动尝试正文GHCV6/7/8和内部体验包的边缘条带，不要求人工填写缩放比例。边缘定位头可加速正文搜索，但几何提示不是身份。
- 只有完整BCH纠错、CRC、规则范围检查及最低5处独立物理观测都通过，才输出可用载荷。相同像素重复扫描不重复计数；两侧载荷冲突明确拒答，不能借另一账号的观测凑数。
- `insufficient_edge_observations`：条带疑似存在但重复数量不足；单侧裁图并不保证可识别。保留原图、左右两侧和更多高度，不拼补账号、不无限重试。
- `conflicting_payloads`：明确记录冲突，不指定身份。只有结合异常/正常角色判断后，才分别裁出各自区域独立解码。
- `decode_timeout`：停止本目标；每图/帧5秒、同Bug合计30秒预算不能因重试重置。失败提示与来源一并记录，继续原日志/代码取证流程。
- `unknown_schema`：完整水印校验通过，但缺少指纹匹配的本地规则；不可套用其他项目字段。依赖故障单独说明，不描述成测试缺少材料。
- 视频用原分辨率PNG帧及实际PTS。仅业务角色明确、完整身份有效时，按项目分析映射交给已有日志工具；注明图片或视频、附件和帧时间、身份是否实际用于查询。不自动请求日志。
- CRC是检错而非验签。转发压缩可能抹除信号；个别QQ样本成功不能外推全部设备或聊天平台。解码核心升级后缓存应随算法哈希失效。
