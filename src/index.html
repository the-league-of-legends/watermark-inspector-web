规则怎么写？

规则就像一张“表单模板”：告诉检查器，每一段数字叫什么、用什么类型、占多少空间。客户端写入和检查器读取时，要使用同一份规则。

  1. projectKey：固定的项目标识，例如 my-project。
  2. schemaVersion：规则版本，从 1 开始；字段有变化时升级版本，并保留旧规则。
  3. fields：按写入顺序列出字段。key 是你自己的字段名，type 是类型，bits 是占用的二进制位数。

保存为 watermark.schema.json，再点击“载入项目规则”。下面是一份占用 105 / 119 位的示例：

{
  "projectKey": "my-project",
  "schemaVersion": 1,
  "fields": [
    { "key": "accountId", "type": "uint", "bits": 63 },
    { "key": "bizId", "type": "uint", "bits": 16 },
    { "key": "capturedAt", "type": "time", "bits": 26,
      "epoch": 1767225600, "stepSeconds": 30 }
  ]
}

uint 是非负整数；63 位可容纳完整长账号。time 从 epoch（UTC 秒）起，每 stepSeconds 秒记一格；示例每格 30 秒。

也支持 int（有符号整数）、bool（是／否，固定 1 位）、enum（用 values 列出选项），以及 string／bytes（用 maxBytes 限制字节数，另占长度位；中文和表情可能占多个字节）。所有字段合计最多 119 位，超出会报错，不会截断。

规则指纹由内容自动计算，相当于模板编号。只改缩进不影响编号；修改字段、顺序或版本会改变编号。载入规则不能改变旧图片的写入格式，指纹匹配后才能解释 GHCV8 字段。GHCV6 / GHCV7 无需规则。
